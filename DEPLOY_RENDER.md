# Render Free + Supabase Free

Режим: сайт и серверный браузер работают на Render Free; данные, история и зашифрованные секреты — в отдельной схеме hh_assistant базы Supabase Free. Render засыпает после 15 минут без запросов и просыпается при открытии сайта. Непрерывная работа 24/7 не обещается. Supabase Free также может приостанавливать неактивный проект; нужно учитывать лимиты аккаунта и API.

## Конфигурация

Dockerfile запускает Python-сервер, Nginx, Xvfb и защищённое окно noVNC для hh.ru. Прямые VNC/WebSocket-порты слушают только localhost. Внешний вход защищён HTTPS Render и HTTP Basic. Имя пользователя — timur, пароль — HH_ACCESS_PASSWORD.

Переменные окружения Render:
- HH_DATABASE_URL — строка PostgreSQL transaction pooler из Supabase Connect, пароль percent-encoded. Проверка TLS: verify-full и официальный supabase-ca.crt.
- HH_MASTER_KEY — стабильный случайный секрет от 32 символов для шифрования. НЕ менять после записи секретов в БД.
- HH_ACCESS_PASSWORD — случайный пароль от 24 символов для личного кабинета и серверного окна браузера.
- HH_MODEL_API_KEY — ключ router.cheap. В настройках выбрать provider router и действующий идентификатор DeepSeek из /v1/models.
- HH_PROFILE_JSON — настоящий профиль соискателя (содержимое локального profile.json), только secret env. В публичном Git — лишь profile.example.json.
- HH_PUBLIC_ORIGIN — необязательно; по умолчанию используется RENDER_EXTERNAL_URL.

Не включать платный persistent disk: Render Free его не поддерживает. Все необходимые изменения хранятся в Supabase. Хранилище браузера экспортируется после действий и шифруется в БД. Некоторые способы авторизации сайта могут потребовать повторного входа после сна — это нужно проверить в реальном сеансе hh.ru.

## Перенос

migrate_cloud.py — локальный одноразовый перенос при остановленном поиске. Его параметры берутся из локального DPAPI Vault, а не из Git. Программа не отправляет отклики во время миграции; в облаке enabled=false и auto_reply=false. Временные файлы Windows, cookies и secrets.dpapi не загружаются в Git.

После запуска открыть кабинет, затем Настройки → Подключение hh.ru → Открыть окно hh.ru на сервере. Там самостоятельно войти и пройти MFA/капчу. Вернуться в кабинет и проверить вход. Капча приостанавливает задания; автоматический обход не реализован.

## Проверки и ограничения

Проверены локальные Python-тесты, браузерные тесты с перехваченными запросами и реальный Postgres read/write/создание HR-задачи/ручная отправка через mock. Linux Docker-образ в текущей Windows-среде не собран: Docker отсутствует. Его сборка, память Render Free и серверный браузер проверяются при первом облачном деплое. На Free-плане памяти может не хватить; успешная проверка обязательна до обещания полной работоспособности.

Ключи, мастер-ключ, пароль БД, доступ к кабинету и profile.json не публиковать. Telegram Mini App не подключён: это отдельный интерфейс поверх того же защищённого сервера, не замена хостингу.
